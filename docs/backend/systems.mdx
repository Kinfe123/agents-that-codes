# Core Backend Systems

The backend page explains request handling, runtime configuration, data-facing services, and the server-side workflow behind the product.
## Purpose and Scope
This area owns request handling, runtime configuration, integrations, and data-facing behavior. It is where the product turns input into persistent state, external calls, or responses.
## What Lives Here
- `app/api/connectors/route.ts` - Route or API layer that receives requests and coordinates runtime behavior.
- `app/api/github/orgs/route.ts` - Route or API layer that receives requests and coordinates runtime behavior.
- `app/api/github/repos/route.ts` - Route or API layer that receives requests and coordinates runtime behavior.
- `app/api/github/user/route.ts` - Route or API layer that receives requests and coordinates runtime behavior.
- `app/api/tasks/[taskId]/route.ts` - Route or API layer that receives requests and coordinates runtime behavior.
- `app/api/tasks/route.ts` - Route or API layer that receives requests and coordinates runtime behavior.
## Operational Shape
- Route or API entrypoints are detected in 11 files.
- `AI_GATEWAY_API_KEY` - API key used to authenticate with the named provider.
- `CURSOR_API_KEY` - Optional API Keys (depending on which agents you want to use)
- `ENCRYPTION_KEY` - Optional Encryption Key (used to encrypt MCP secrets in the database)
- `VERCEL_TEAM_ID` - Vercel Sandbox Configuration
