## Core Capabilities
- Developer Tools: This section explains the utilities that help developers inspect, configure, or generate parts of the product. These tools are not just UI screens; they are shortcuts for common setup, debugging, schema, email, or integration work. Key concepts: developer tools, generators, inspectors, visual editors.
- Session Management: This area explains how the product observes active authentication state. It connects user identity, session creation, sign-in activity, cookies or tokens, and any security-sensitive controls exposed to administrators. Key concepts: sessions, sign in, tokens, cookies.
- User Management: This capability is the administrative surface for user records. It helps an operator inspect accounts, find a user by identity, update profile or verification state, and remove records when needed. In an auth-oriented product, this page is usually one of the highest-value docs pages because it explains the exact model an admin interacts with. Key concepts: users, accounts, profiles, email verification.
- Organization Management: This capability documents the multi-tenant administrative model. It explains how organizations group users, how teams subdivide access, and how membership or invitation actions change what a person can do inside the product. Key concepts: organizations, teams, members, invitations.
- Event Tracking: This capability turns runtime activity into a timeline that administrators can inspect. It is especially useful for auth products because sign-ins, session creation, account updates, and organization events often need auditability and context. Key concepts: events, audit trail, activity feed, last seen.
- Self-Hosting Overview: Self-hosting explains how the package runs inside or next to a user's own application. It clarifies which pieces are required at runtime, how the host app mounts the product, and what infrastructure must be available in production. Key concepts: runtime dependency, host application, deployment, container.
- IP Geolocation: IP geolocation enriches security and activity views with approximate location context. It usually depends on a provider or database file, so this page separates required config, optional provider tokens, and privacy-sensitive behavior. Key concepts: IP address, geolocation provider, GeoLite, session metadata.
- Database Adapters: Database adapter docs explain how the product connects to the same persistence layer as the host auth system. They identify supported adapters, the expected provider names, and what needs to be migrated before the UI can read or write records safely. Key concepts: Prisma, Drizzle, SQLite, Postgres.
- Access Control: Access control defines who can open and operate the administrative surface. This page explains the relationship between roles, explicit email allowlists, IP rules, and the default behavior when no rule matches. Key concepts: roles, allowlist, blocklist, admin access.
- Metadata: Metadata controls how the product presents itself to administrators. This usually includes title, theme, branding, and other non-functional settings that make the embedded experience feel native to the host application. Key concepts: title, theme, branding, labels.
- Event Ingestion: Event ingestion describes how activity enters the product. It explains provider responsibilities, event shape, helper functions, and how ingested events become visible in dashboards, timelines, or last-seen fields. Key concepts: event provider, event type, severity, helpers.
- Troubleshooting: Troubleshooting turns known setup failures into clear recovery paths. It connects symptoms to likely causes, points at the files or settings to inspect, and gives safe verification steps. Key concepts: configuration discovery, runtime errors, database migrations, permissions.
- CLI Usage: CLI usage explains the command-line mental model: which commands exist, when to use each command, which flags affect runtime behavior, and how the CLI discovers project configuration. Key concepts: commands, flags, config discovery, local development.
- Custom Branding: Custom branding explains how the embedded experience can match the host product. It helps developers understand the difference between visual customization and behavior-changing configuration. Key concepts: brand title, theme, logo, metadata.
- Watch Mode: Watch mode is the development feedback loop. It keeps the product aligned with local configuration changes by monitoring files, restarting or refreshing the runtime, and reducing manual browser refreshes. Key concepts: file watcher, reload, config changes, development loop.
- Bulk Operations: Bulk operations help operators or developers create, update, export, or seed many records at once. This page explains safety boundaries because bulk actions can change a lot of data quickly. Key concepts: bulk actions, seed data, import, export.
